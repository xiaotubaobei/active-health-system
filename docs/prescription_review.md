# 处方人工审核：本地使用与验收

## 现在能做什么

用户将**某一版处方**提交给指定审核账号，主动授权查看本次处方、档案和最近测评快照。审核人填写意见并选择通过或退回。通过将该版状态改为 `formal_prescription`（正式处方），不修改动作、强度或用药，不增加处方版本。退回保留原处方，用户可补充说明后再次送审，或更新档案、生成新版后送审。

这是项目内的审核流程。现有处方仍来源于规则模板；人工点击通过不代表模板已经获得临床有效性验证。训练演示仍可使用预处方，不要求先通过审核。

## 第一步：准备审核人账号（项目维护人员操作）

1. 审核人在登录页注册自己的个人账号，例如 `zhang-doctor`，自行设置密码。不要使用保留账号 `physician`、`specialist` 或 `admin`。
2. 正常启动后端一次以创建数据库表。在项目根目录的 PowerShell 中，用运行后端的同一个 Python 环境执行：

   ```powershell
   python scripts/set_user_role.py --username zhang-doctor --role physician
   ```

   健身处方师则执行：

   ```powershell
   python scripts/set_user_role.py --username li-coach --role prescription_specialist
   ```

   工具只修改已存在账号，不创建账号或默认密码。它使用 `DATABASE_URL`，请与后端指向同一个数据库。若使用项目虚拟环境，可把 `python` 换成 `.venv/Scripts/python.exe`。
3. 告诉用户审核人的**准确账号名**。角色变更会撤销该账号的所有登录凭证，审核人需重新登录。审核账号可直接访问「处方人工审核」，无需为审核用途填写个人首次测评。
4. 取消审核资格时执行 `--role user`。尚未处理的申请会留在用户记录中，用户可以撤回并改交其他人；被取消资格的账号不能再读取审核列表或作出决定。

请由项目负责人核实人员身份后设置角色。注册和网页接口不能自行提升角色，管理员身份本身也不赋予医疗审核权。

## 第二步：用户送审

1. 登录普通账号，完成首次测评，打开「运动处方」。
2. 在「提交人工审核」填写审核人账号和需要关注的问题。
3. 阅读资料共享范围，勾选同意，然后点「提交审核」。医疗模板只能交给医师；健身模板可以交给医师或处方师；不能自己审核自己。
4. 「我的审核记录」可以看到版本、审核人、提交说明、处理意见、时间及送审快照。记录超过10条时可翻页。
5. 等待期间可以点「撤回申请」。生成新版会自动使本人所有旧的待审申请失效；旧版不能继续审核，新版需要重新提交。已通过或已退回的历史结果不受影响。

## 第三步：审核人处理

1. 重新登录审核账号，打开「处方人工审核」。
2. 在待审核列表展开「查看处方、档案和测评快照」。包括运动安排、健康计划、年龄组、身高体重、目标、慢病标签和最近一次测评。没有测评会明确提示。
3. 填写审核意见（必填，最多2000字），点「审核通过」或「退回补充」。
4. 切换「已通过 / 已退回」可以回看自己处理的记录；用户也能在自己的处方页看到相同意见。

审核人只得到本次明确提交的资料，不因此获得用户训练历史、报告、视频或全部档案接口的访问权。撤回或生成新版后，未处理快照不再出现在审核人列表中，后端也拒绝处理。已经看过的资料无法从对方记忆中撤销；已完成的审核记录对双方保留。

## 状态与记录规则

| 申请状态 | 含义 | 处方变化 |
|---|---|---|
| `pending` | 等待指定人审核 | 保持预处方或监测状态 |
| `approved` | 审核通过 | 本版标记为正式处方 |
| `rejected` | 审核退回 | 保持原状态，可再次送审 |
| `cancelled` | 用户撤回 | 保持原状态 |
| `superseded` | 已生成新版，旧申请失效 | 新版仍需送审 |

每次送审生成独立记录，固定当时的处方、档案和测评。用户后续修改个人档案不会覆盖旧快照；审核人以快照为依据，不自动读取最新个人数据。审核决定只能写一次，重复提交决定返回409，避免覆盖原意见。生成、送审、撤回及决定按同一用户串行处理；待审处方编号还受唯一约束保护。

原有直接推进接口 `/prescriptions/{id}/advance` 已停用：本人普通账号返回403，具有角色的本人返回409并提示走审核流程，其他人返回404。

## 验证范围

后端自动测试使用临时 SQLite，涵盖正常通过、退回重送、撤回、资料授权、跨账号隔离、医师/处方师范围、权限撤销、旧版本失效、快照固定，以及并发重复送审、重复决定、生成新版与审核同时发生、撤回与审核同时发生。前端生产构建通过，并以临时用户和医师账号在浏览器完成送审、查看快照、填写意见、通过及用户回看正式处方和审核记录。

后端首次启动会自动创建 `prescription_reviews` 表，本次开发验证不迁移项目现有数据库，也不修改已有真实账号角色。真实医师身份核验、临床验证、处方内容人工编辑、多级会诊与机构级权限管理尚未实现。
