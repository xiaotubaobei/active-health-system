# 目前进展与还缺的功能

日期：2026-11-25。当前定位仍是能跑通主流程的试用版，尚未完成上线与手机真机验收。

## 现在可以做什么

注册登录 → 首次测评 → 生成模板训练计划 → 选择动作 → 视频或摄像头采集姿态 → 保存与恢复训练 → 结束归档 → 查看报告与训练历史。另有处方人工审核、测量记录、备份与恢复工具。

其中，姿态采集、保存和业务流程已实现；动作计数和评分是否有效取决于真实算法服务，备用结果不会被当作有效成绩。

## 本轮新增：训练后的本人反馈

从「训练历史」打开已完成训练的报告，在「这次练得怎么样？」填写：

1. 先选择本人实际训练，或仅体验演示/样本。
2. 本人实际训练时，选择完成情况、累不累、有没有不适；可以再写一句说明。
3. 点击保存。之后从同一报告回看、修改，刷新后仍保留。

各项初始为空，不替用户默认填写“已完成”或“没有不适”。仅体验样本不记录本人的完成量与身体感受。反馈不会改动模型成绩或自动调整训练计划。

保存失败保留本页内容，可以重试；另一页面先修改时停止覆盖并提示核对。离开、切换报告或重新加载前会提醒未保存内容。浏览器关闭或刷新前尚未保存的内容仍可能丢失，不承诺离线同步。

顺带修复手动切换训练编号后网址未更新的问题，刷新和分享链接会指向当前训练。

更新前按部署说明停站备份，更新后重启后端即可自动建表，无需手工修改旧数据。

## 补充审查：字段和建议是否对应真实用户

结论：业务流程能跑通，但目前仍是模板试用版，不能当作已经完成的个体化运动健康系统。判断字段是否合理，要同时回答四件事：用户能否如实提供、单位与采集方法是否明确、数据是否可追溯、它实际影响了哪条建议。多填几个字段或用模型改写措辞，不能代替这些条件。

### 已核对的字段与缺口

| 字段或信息 | 当前实际情况 | 应怎样改，收集后用于什么 |
| --- | --- | --- |
| 年龄组 | 只有青少年/中年/老年，没有年龄和明确划分依据 | 后续按选定标准需要收集年龄或出生年月，并记录采集日期；规则负责划分，不能让用户猜“中年”从几岁开始。年龄用于选择适用标准和活动建议人群，不单独决定运动量 |
| 身高、体重 | 可填测量值；注册层仍存在170/65历史占位。缺少测量日期和来源 | 本轮首次填写改为空，后台必须明确提交。后续记录测量日期、本人测量/设备导入等来源；不会测或不清楚时允许待补充，暂停依赖它的计算。修改当前档案不得改变过去测量的基数 |
| 性别等标准适用条件 | 尚未收集，也没有确定采用哪套评分标准 | 先确定标准。只有确实影响该项换算时再询问相应条件，说明用途，支持暂不提供；缺失时不输出依赖该条件的分数。不为填满档案而收集敏感资料 |
| 运动目标 | 只有健身/医疗，是业务分类，不是具体目标；中年健身默认选减脂模板 | 后续用提高日常体力、改善力量/平衡等用户能理解的具体目标，加上本人优先级；不能默认每个中年用户都想减脂。目标不能替代健康情况评估 |
| 慢病标签 | 自由输入英文，空数组无法区分“没填”和“确认没有”；任意标签都转医疗库 | 改为明确的有/无/不清楚，再记录本人已知诊断及运动限制、来源与更新时间。普通用户不应填写内部标签。未知病种不能推断成无病，也不能随便匹配另一种病的模板 |
| 体适能各项 | 青少年是BMI、肺活量、50米跑、坐位体前屈、跳绳、仰卧起坐、立定跳远；中老年是形态、力量、柔韧、平衡、协调、日常活动。当前全部要求0–100换算分，缺少测试方法和换算表 | 每项要定义具体测试、原始单位、测试日期、执行方法、适用人群和标准版本。例如“力量”“平衡”仅是维度，不能直接让用户猜分。允许未测、不能测、待补充；不能随便把不同测试结果混在同一分数里 |
| 总分、等级 | 权重来自申请书骨架；85/70/55分档没有在当前代码中给出标准来源 | 本轮去掉页面“优秀/达标/可进阶”等结论。先核验标准和分档依据，缺少必要条件时不给等级。原始成绩、换算分和模型动作评分是不同数据，不能互相替代 |
| 腰围、臀围、BMI、腰臀比、体脂率 | 围度可填实测值；BMI依赖当前档案。体脂率未输入时后端仍存0，历史没有保留原始身高体重与围度 | 后续保存同次测量快照及日期；没有体脂测量应为未知，不能写成0。新旧数据迁移需要区分已测0与缺失占位，不能凭数字猜来源。当前未验证的旧数据不应用于个人建议 |
| 运动基础与条件 | 尚无平时运动量、可安排时间、场地器材、动作偏好，以及疼痛/活动限制等资料 | 按用途分步询问；训练时间和器材用于安排可执行的动作，身体限制用于专业评估及动作适配。具体筛查问题和处理规则需专业人员确认，不自行编造禁忌、风险分或诊断 |
| 计划强度、频次、时长、组数、进阶 | 来自固定模板；测评和训练反馈没有参与制定。医疗模板年龄匹配失败会回退其他年龄，标签不匹配也会取首个候选 | 优先移除无匹配时随便选模板的回退。无适用方案时明确待评估；档案保存与生成计划应拆开。之后为每个参数记录依据、适用范围与确认人，不用总分或BMI直接猜运动量 |
| 饮食、睡眠、用药、心理建议 | 旧模板固定写“均衡饮食”“保证7小时”；空用药、心理原来显示“无” | 本轮新计划不再填固定文字，空值显示“未评估”，旧文字提示模板来源。真正提供专项建议前，先有对应资料、标准和专业审核，不仅根据年龄或标签生成 |
| 训练完成、费力程度、不适、备注 | 已支持本人填写，初始为空；区分实际训练与体验样本。尚未驱动人工跟进或计划调整 | 保留本人反馈，不用录制时长推算实际训练量。后续不适需要补充部位、发生时间及本人描述，再建立专业人员查看、回复和调整记录；不凭一句“累”自动减组或诊断 |
| 视频、姿态、计数、模型分数、模型建议 | 已区分演示与有效服务输出；模型返回正常不代表算法效果已经验证 | 记录采集来源、算法版本和数据质量；用人工标注验证计数和错误识别。模型建议必须受已核实事实和适用规则约束，不能凭视频推断慢病或整体健康状况 |
| 设备读数 | 目前是通用JSON写入接口，未完成真实设备对接 | 接入具体设备时才定义测量指标、单位、采样时间、设备型号及质量标记；没有真实读数不显示正常值，不参与个体建议 |
| 隐私同意和审核 | 有本人同意、指定审核人及版本快照；审核当前只能通过/退回，不能修改运动参数 | 按必要用途采集和授权，保留撤回机制；补充专业人员可编辑计划及变更理由。系统角色名或一次“通过”不等于已完成临床有效性验证 |

### 本轮已经改的内容

1. 首次填写不再默认170厘米、65公斤，也不默认年龄组和目标；接口缺少这四项中的任何一项都拒绝建基线。注册旧占位和历史记录未做猜测性改写。
2. 测评页去掉基于总分的“整体达标、逐步进阶、柔韧平衡短板”等结论；首次基线和送审快照明确为试验汇总，录入时间不冒充测量时间。接口旧分档暂留作兼容，不代表已验证等级。
3. 新模板不再自动填饮食、睡眠建议，页面空值统一显示“未评估”，并提示旧文字来自模板。
4. 档案保存和计划页明确当前哪些数据没有参与制定，更新档案不会自动改写已有计划。

这些修改减少误导，没有把模板系统变成个体化指导。首次测评仍阻塞没有换算分的人；未知健康标签的模板回退、旧占位、未测体脂存0等问题仍待后续修改。

### 接下来按这个顺序做

1. **先让真实资料能录进去。** 将基本档案与专业测评分开，支持未测/不清楚；为测量保存原始值、单位、测量时间、来源和历史快照。删除不适用模板的回退，缺信息时显示待补充，不凑出一份计划。
2. **再让计划有依据。** 与负责人和专业人员选定适用标准，整理可用动作及适配规则；对每条建议保存使用的数据、规则/标准版本、原因、待确认事项。专业人员可以编辑再确认。模型只解释已有依据，不补造事实或临床规则。
3. **最后验证能否持续用。** 用资料完整、未测分数、慢病且有活动限制、缺少器材、训练后不适等不同的虚构案例检查流程；确认建议差异来自哪些输入。算法另用标注样本验证，实际用户试用、专业评审和手机验收单独记录。

例如：同样选择“健身”的两个人，一个缺测评、一个有活动限制，系统应显示不同的待补充或待评估事项；不能仅因为年龄组一样就给同一份“减脂、每周加量”计划。这是后续验收要求，不是已经实现的能力。

参考边界：[WHO身体活动指南概要](https://www.who.int/publications/i/item/9789240014886)按人群提供公共健康建议，包含慢病和残障人群；不能将人群层面的建议直接当作本人的个体化处方。具体量表换算、运动适配及医疗规则仍须核验相应标准与专业意见。

- 生成模板前先检查目录。不同年龄组不再互相兜底；医疗标签必须完整一致，不接受仅有一个标签重合、未知标签或缺少适用情况时套用首个模板。目录匹配只表示找到同类模板，不代表已经完成个人运动适配。
- 方案页显示匹配情况和原因；不匹配时停用生成按钮。生成失败不新增版本、不撤销正在处理的审核，旧方案与用户已填资料保留。旧版接口请求建档时若要求生成但没有匹配，也会保存有效档案与测评，并返回无匹配原因。
- 注册占位资料不能直接生成方案。首页、导航及相关入口改为“建档”“模板草案”等实际含义。
