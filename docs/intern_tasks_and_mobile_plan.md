# 两位实习生分工与手机端交付计划

更新日期：2026-11-18。本文是任务分工与验收计划，不代表所列功能已经完成。

## 一、这次要交付什么

第一版目标：普通用户不需要开发者在旁边解释，就能用手机完成注册、填写档案、查看训练计划、完成一种受支持的训练、查看报告，下次进入还能找到记录。

先完成手机网页，再增加“添加到手机桌面”的入口。第一阶段不另建 Android/iOS 原生应用，也不要求实习生训练算法。

部署、摄像头兼容性、真实评分分别验收：能打开网页不等于摄像头可用，能画出骨架不等于模型评分有效。

## 二、分支与当前代码基线

- A 同学使用 `a`，B 同学使用 `b`。
- 两个分支最初从 `cc79b56` 创建；本轮交接将人工审核功能、相关测试和分工文档统一提交，作为两人的共同起点。集成工作分支为 `feat/personal-kb`。
- 本轮获准同步 GitHub，更新 `main`、`feat/personal-kb`、`a`、`b` 到同一交接提交，之后两位同学分别在自己的分支开发。
- 不把数据库、上传视频、本机环境、依赖目录和模型文件纳入提交。首次克隆后按 README 准备依赖及所需演示资源。
- 后续集成以正常合并为准，不强制覆盖已有工作。两人开工后，不再把各自分支重置到集成分支。
- 两人各自在自己的电脑/独立克隆中工作。同一工作目录中切换分支不会隔离未提交文件，不要两人共用这个工作目录。

首次获取代码（在各自电脑执行，A 使用 `a`，B 将下面的 `a` 改成 `b`）：

```powershell
git clone --branch a https://github.com/xiaotubaobei/active-health-system.git
cd active-health-system
```

如果已有克隆，先保存自己未提交的修改，再执行 `git fetch origin` 和 `git switch a`（B 使用 `b`）。已有本地分支只使用正常合并或 `git pull --ff-only` 更新；失败时联系集成人员，不执行强制重置。

共同约定：只提交自己任务的文件，不提交数据库、上传视频、账号密码、模型、依赖目录或本机配置。每天提交一个可检查的小成果。遇到接口不够用，先记录需要的数据和用途，由集成人员确认后端改法。

## 三、A 同学：用户入口和手机页面

### A1. 把首页改成个人工作台（必做）

主要文件：`frontend/src/views/Home.vue`。

具体做法：

1. 首页展示用户名、当前训练计划、已完成训练数和最近训练记录。
2. 有未完成训练时显示“继续上次训练”，进入原来的训练编号；不要创建一条新训练。
3. 没有未完成训练时显示“开始训练”，另外提供“查看训练计划”。
4. 最近完成的训练提供“查看报告”，使用该条记录的编号跳转，不要求用户记编号。
5. 没有记录时解释“还没有训练记录”，提供开始入口；没有计划时提供生成计划入口。
6. 请求失败显示“重新加载”。读取失败不能被显示成“0次训练”或“没有计划”。
7. 把一键演示放进单独的“体验演示数据”区域，说明不会产生有效评分；不作为首页最主要按钮。

复用接口：

- `GET /prescriptions/current?user_id=当前用户ID`：当前计划；只有确实返回“尚无处方”的 404 才当作空计划。
- `GET /users/{id}/kb/summary`：完成训练与归档统计。
- `GET /users/{id}/sessions/page?page=1&page_size=3`：最近记录。
- 同一分页接口加 `status=running&page_size=1`：查找未完成训练，不只在最近三条里查。
- 前端请求继续使用现有 `api/client.js`，不要写死用户ID或服务地址。

验收：分别用无记录账号、已有完成记录账号、有未完成训练账号检查；首页按钮都能进入正确位置。接口关闭时有错误与重试入口。

### A2. 整理导航与普通用户文案（必做）

主要文件：`frontend/src/App.vue`、`frontend/src/views/Login.vue`、`frontend/src/views/Profile.vue`。

1. 普通用户的主要入口为：首页、训练计划、开始训练、训练记录、个人档案；体适能评估保留在容易找到的次级入口。
2. 审核角色提供审核入口；普通用户不展示审核人员工作台入口。此项是界面整理，不能替代后端权限校验。
3. 体型解析、设备模拟等未完成内容放到“实验功能”，明确标注状态。不要删除已有实现。
4. 去除面向用户的“图14、CoT、桩、框架阶段”等开发文案，替换为实际用途说明。
5. 慢病字段给中文说明；若做中文选项，必须由集成人员提供与现有标签值的映射，不能直接把存储值换成中文。
6. 表单添加清晰单位、填写说明、保存中和保存结果。保留既有同意提示和错误提示。
7. 不改审核组件、处方状态、登录凭证存储或权限判断规则；涉及路由新增先与集成人员协调。

验收：普通用户不会误以为自己能管理系统；登录、退出、档案保存仍能工作；切换账号后首页不残留上一个人的数据。

### A3. 手机基础布局（必做）

主要文件：`frontend/src/assets/style.css`，以及自己负责页面的局部样式。

1. 在 360、390、430 像素宽度检查首页、登录、档案和导航，无横向滚动和文字遮挡。
2. 主要操作按钮容易点击，点击区域目标至少 44×44 像素；手机键盘弹出后仍能滚动到提交按钮。
3. 导航能展开、关闭；点击目标后收起。当前页面位置清楚。
4. 保留电脑布局，不用固定宽度把表单挤出屏幕。
5. 先提供统一的间距、按钮和表单样式，告诉 B 同学怎么复用，避免两人各做一套。

验收：提交手机宽度截图；有真机时记录型号、浏览器和操作结果。模拟手机宽度通过不能写成真机通过。

### A 的后续任务（首周完成后再做）

配合集成人员增加网页应用名称、图标和安装说明，让支持的浏览器可添加到桌面。HTTPS、部署和缓存策略由集成人员统一处理，不自行缓存账号数据、健康报告或上传视频。

## 四、B 同学：测评、历史记录与报告

### B1. 测评填写说明与表单体验（必做）

主要文件：`frontend/src/views/Onboarding.vue`、`frontend/src/views/Fitness.vue`。

1. 每项说明清楚现在录入的是“体测换算分”，不是次数、秒数或体重。
2. 标注必填项和有效范围，空值和错误项在对应字段旁说明，提交后定位第一个错误项。
3. 用中文展示量表名和等级，不向用户直接展示 `middle_elder` 等内部标识。
4. 量表加载失败、提交失败能重试，失败后尽量保留已填内容，避免用户重新录入。
5. 完成测评后显示总分和清楚的下一步入口，例如查看训练计划；不显示接口原始对象。
6. 梳理“没有体测分数的人怎么办”的页面方案，交集成人员确认；首周不自己绕过首次测评约束或补默认分。
7. 不编造原始成绩到分数的换算标准，不改权重和评分规则。

验收：检查空值、0分、100分、小数、超出范围、切换量表、断网重试，确认没有把空值当0分，也没有丢掉错误提示。

### B2. 训练历史更容易找（必做）

主要文件：`frontend/src/views/History.vue`。

1. 每条记录优先展示动作、时间、完成状态和可做的操作，编号作为次要信息。
2. 保留状态筛选、动作筛选和分页；更换筛选后回到第一页。
3. 未完成记录提供“继续训练”，完成记录提供“查看报告”，取消记录不展示错误的继续入口。
4. 区分“从未训练过”“筛选后没有结果”“读取失败”三种情况，分别提供开始训练、清除筛选、重新加载入口。
5. 明确标注演示/备用结果，不把它们显示成有效评分或加入模型成绩比较。
6. 手机下每条记录布局清楚，按钮不挤在一起。

验收：无记录、有多条记录、有未完成和取消记录、筛选无结果、翻页都能操作；从记录打开的是它自己的报告。

### B3. 报告改成用户能看懂的结果（必做）

主要文件：`frontend/src/views/Report.vue`。

1. 优先展示本次动作、训练时间、评估状态和实际完成情况；只展示真实返回的数据。
2. 从历史页进入自动加载对应报告，不把手工输入训练编号作为主要方式。
3. 直接进入报告页且没有可用训练记录时，显示“暂无可查看的报告”，提供去训练和查看历史入口。
4. 有有效模型结果时展示分数、问题和建议；没有时解释原因，不展示演示75分等替代分数。
5. 有动作计数才展示次数；没有计数显示未获取，不能编一个完成次数。
6. 原始服务结果放在次级折叠区域，默认不展开；用户不需要理解JSON。
7. 加载中、无报告、无权限/记录不可用、服务失败有明确提示，不能一直停在空白页。

验收：真实有效结果、演示结果、无姿态数据、没有报告、错误编号分别检查。没有真实模型样例时注明“此分支未验真实模型”，不可伪造验收结论。

### B 的后续任务（首周完成后再做）

整理动作使用说明和经过确认的示范资源，补充手机操作测试记录。测评历史接口和趋势图待后端提供数据后再排期，不在首周承诺完成。

## 五、由集成人员负责的工作

这些内容由项目负责人和协助开发者推进，不作为实习生首周独立交付要求：

1. 整理共同代码基线，合并两人修改、解决冲突、检查身份权限与跨账号隔离。
2. 把计划中的动作与训练入口衔接，定义整套训练完成规则及对应计划版本。
3. 完善摄像头分段保存、刷新恢复、结束训练失败重试和防止重复归档。
4. 真实姿态服务与动作评估联调，明确支持哪些动作、输入条件和无效结果；不把演示报告包装成算法完成。
5. 审核流程与处方编辑、版本关联，以及个人档案变更后的计划提示。
6. 修改密码、密码找回方案、登录失败限制和必要操作记录。
7. HTTPS部署、服务配置、模型资源可访问性、数据备份恢复、服务重启与错误定位。
8. 手机摄像头权限、前后摄像头、浏览器兼容与性能检查。不能只根据电脑浏览器验收。

## 六、手机端推进路线

### 第一步：手机网页可以使用

完成上述页面适配；先打通注册、档案、计划、训练记录和报告。测试环境由集成人员提供手机可访问地址。当前 `127.0.0.1:5173` 只指向访问设备自身，不是发给手机就能访问的地址。

临时同一Wi-Fi访问还涉及监听地址、允许来源与网络访问配置。HTTP局域网地址可以用于基础页面检查，不作为手机摄像头验收方案。不直接对公网开放开发服务器。

### 第二步：提供可验证的HTTPS试用环境

集成人员准备部署目标、域名/证书和配置：

- 对外一个HTTPS地址，提供生产构建的前端，同源转发 `/api`，页面刷新仍能打开正确路由。
- 配置允许来源、HTTPS会话Cookie和上传限制；关闭默认演示账号。
- 算法服务、数据库留在受控内部连接，不直接公开服务端口。
- 记录数据库与视频存储位置，验证备份和重启后数据仍在。
- 核查浏览器姿态模型与WASM资源在手机所在网络可加载，必要时统一调整资源托管。

部署目标、域名和真实测试手机尚未落实，所以此文不表示部署或真机验收已完成。

### 第三步：手机训练与添加到桌面

- Android Chrome、iPhone Safari分别记录实际设备与系统版本；拿不到某类设备就明确该项未验证。
- 检查权限允许、权限拒绝、模型加载失败、切后台再返回、屏幕旋转、短时断网和再次登录。
- 先让一种短时训练稳定完成，再测试较长训练的帧率、内存和保存行为。
- 摄像头需在安全上下文运行，部署通常使用HTTPS；不能用“局域网HTTP网页能打开”推断摄像头也能工作。
- 增加网页应用清单、图标、独立窗口配置和添加到桌面说明，按各浏览器实际能力验收。添加桌面不代表能离线评分或后台持续录像。
- 不缓存个人健康API、登录信息和训练视频；离线训练、自动同步、消息推送另行设计。

参考：[MDN 摄像头与安全上下文](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)、[MDN 网页应用安装条件](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)。

## 八、文件归属与交付方式

| 范围 | 负责人 |
|---|---|
| Home.vue、App.vue、Login.vue、Profile.vue、全局style.css | A |
| Onboarding.vue、Fitness.vue、History.vue、Report.vue | B |
| 路由、共用API封装、Exercise.vue、Prescription.vue、Reviews.vue、后端、部署和安装配置 | 集成人员 |

B 的页面样式优先写在各页面的 `<style scoped>`，复用A提供的全局样式。需要改别人的文件时先约定，不能两人同时重写导航或全局样式。

每人交付：代码提交、改动文件清单、每项验收结果、电脑与手机截图、仍存在的问题及复现步骤。只在自己的分支提交，交给集成人员检查合并，不自行合并到 `main`。

前端运行 `npm run build`。若涉及后端，由集成人员运行 `python -m pytest backend/tests -q`。构建通过不替代实际页面操作和手机验证。

最终验收主线：新用户注册 → 建档/说明测评状态 → 查看计划 → 完成受支持训练 → 查看报告 → 关闭再进入找回记录。由未参与开发的人独立操作，并记录卡住的位置。所有“演示”“待接入”“未验证”如实标注。
