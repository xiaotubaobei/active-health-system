# 账号、个人数据隔离与本地部署

## 已完成的行为

- 注册只创建普通用户；密码为 8–128 字符，不再提供默认注册密码。数据库保存随机盐的 PBKDF2-HMAC-SHA256 哈希（600,000 轮），参数依据 [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。登录与个人接口均不返回密码。
- 登录凭证由服务器随机生成，数据库只保存摘要，有效期 8 小时；浏览器通过 HttpOnly、SameSite=Lax Cookie 使用，不将凭证存入 localStorage。重新登录替换该浏览器原凭证，其他设备不受影响；退出立即撤销当前凭证。
- 页面刷新或切换时重新向后端确认身份；凭证失效后返回登录页。个人资料、测评、处方、训练、报告、设备记录、知识库及上传文件只允许所属账号访问。替换用户编号或训练编号不能访问别人的记录。
- 普通账号不能创建专家 / 医师角色或推进处方审核状态；演示训练不调整处方。医师与患者之间的授权和审核流程仍待实现。
- 本地演示账号默认关闭。开启后只允许普通账号 `demo / 123456`；原先默认的 `specialist`、`physician`、`admin` 禁止登录。

## 启动配置

默认手动启动适合本机开发，可直接注册个人账号，无需设置密钥。所有配置都在启动后端前设置，修改后需要重启。

| 环境变量 | 默认值 / 用途 |
|---|---|
| `ENABLE_DEMO_ACCOUNTS` | `false`；只在本地演示时设为 `true`，一键启动脚本已显式开启 |
| `COOKIE_SECURE` | `false` 兼容本机 HTTP；HTTPS 部署必须设为 `true` |
| `ALLOWED_ORIGINS` | 本机 localhost / 127.0.0.1 的 5173、8000 端口；多个完整来源以逗号分隔，不支持 `*` |
| `DATABASE_URL` | 项目根目录 `active_health.db`；测试使用独立临时数据库 |

本机演示示例（PowerShell）：

```powershell
$env:ENABLE_DEMO_ACCOUNTS="true"
cd backend
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

如后续部署 HTTPS，应关闭演示账号、设置 `COOKIE_SECURE=true`，并把 `ALLOWED_ORIGINS` 限定为实际前端地址。建议前端与 API 使用同一站点代理；现有 SameSite=Lax Cookie 不用于跨站嵌入。AI 服务保留内部访问，不直接对公网提供读取本机媒体文件的接口。本轮没有完成公网部署，还需补充登录限流、密码重置、操作审计及部署验证。

## 旧库与视频兼容

后端启动会创建 `auth_sessions` 表，把旧明文密码升级为哈希，原有密码仍可登录。迁移可重复执行，不覆盖训练和报告；旧开发 token 不再有效，需重新登录。当前轻量补列迁移面向 SQLite，其他数据库的历史结构变更需另行迁移。

视频按用户目录和随机文件名存储。只有公共 `data/demo_videos/` 和本人 `uploads/offline/<用户编号>/` 下的媒体可用于推理或训练；公共样本兼容 `demo_videos/...` 别名。旧共享上传文件需本人重新上传，已有完成报告仍可回看。服务器上传限制为 100 MB；浏览器本地分析没有上传文件时只保存姿态摘要。

## 验收步骤

1. 手动启动后端，不设置演示开关。`demo / 123456` 应被拒绝；注册两个不同账号 A、B，每个账号完成首次测评。
2. A 完成一条演示训练，记下训练编号；刷新后应仍可查看报告。当前处方不显示审核推进按钮。
3. 退出 A，再尝试访问历史页，应返回登录页。登录 B 后，不能打开 A 的报告；手工调用 A 的资料、训练、知识库接口也应返回 404。
4. A 上传的视频不能由 B 引用。A 连续上传两个同名视频，服务器应返回不同路径。
5. 自动检查覆盖过期 / 伪造凭证、退出撤销、旧密码迁移、跨账号读写、禁止角色提升、来源校验与上传隔离。运行 `python -m pytest backend/tests -q`；测试使用临时数据库。

本轮使用临时库完成了自动检查、API 冒烟和浏览器登录 / 刷新 / 退出验证，没有迁移项目现有数据库；实际启动项目时才会执行其迁移。
