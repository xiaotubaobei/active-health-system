# 用户流程实测与下一步

日期：2026-11-24。本轮使用独立临时数据库和虚构账号，未修改现有用户库。

## 现在实际能做到什么

浏览器里走通了：注册 → 首次测评 → 生成训练计划 → 选计划中的深蹲 → 解析短视频 → 开始训练 → 刷新恢复 → 结束训练 → 查看报告 → 从历史记录找回报告。

视频解析使用推荐的 RepCount 深蹲片段 `repcount_stu4_66.mp4`，浏览器 MediaPipe 提取到 55 帧姿态。姿态提取是真实执行的；本轮没有启动真实评分、动作计数服务，报告正确显示“暂无有效评分”和“演示 / 备用结果”，不计成绩，也不自动调整处方。

这说明主流程已经能运行，尚不能据此认定算法有效或成品已经验收。

## 本轮发现并修复的问题

| 问题 | 修复后的表现 |
| --- | --- |
| 首次进入也提示“登录过期” | 只有曾登录的账号凭证失效时才提示过期；新访客正常进入登录页 |
| 打开报告后登录，原来的页面丢失 | 登录后回到原页面，保留训练编号等参数；拒绝外部返回地址 |
| 后端暂时不可用，被带回登录页 | 单独显示连接失败与重试入口，保留账号缓存；恢复后重试回原页面 |
| 错误网址显示空白 | 显示“没有找到这个页面”，提供首页和训练历史入口 |
| 负腰围、零臀围也能保存 | 页面和接口都拒绝无效数值，不写入记录；有效小数可保存 |
| 身高、体重等输入无效时显示原始错误对象 | 显示对应字段的中文提示，失败不修改已保存档案 |
| 体型页默认填写未经测量的围度，演示点击像真实识别 | 围度初始为空；主要功能改为实测记录，模拟部位解析单独折叠并说明 |
| 恢复视频训练后提示重新选文件，但文件输入不可用 | 明确说明已保存姿态可直接生成报告，视频预览不会恢复 |
| 视频训练也显示摄像头采集说明，未解析就称已解析 | 根据输入方式和实际数据状态显示说明 |

接口数值上限用于拦截明显输入错误，不是临床正常范围。BMI、腰臀比保留计算展示，不作新的健康风险分级。

## 接下来优先做什么

1. **A 同学：让普通用户一进来知道该点哪里。** 按现有分工完成个人首页、未完成训练入口、角色导航；移除“图14”“CoT”等开发文案。普通用户目前仍能看到审核和管理入口，虽然审核页有权限拦截，体验上仍容易误解。
2. **B 同学：把测评填写解释清楚。** 现在需要输入 0–100 的换算分，普通人不知道怎么得到；先标明填写来源、逐项提示、提交后的下一步。无测评分数时如何开始，由负责人确认，不补默认分或自行制定医学换算规则。
3. **主线：部署到 HTTPS 测试地址后做真机验收。** 先验收注册、视频训练和报告，再检查 Android / iPhone 摄像头授权、后台暂停、弱网、退出恢复。当前仍是本地验证，不是已上线。
4. **负责人：接通并验证算法服务。** 用固定视频记录真实计数、评分和失败表现。没有真实结果时继续保留明确的备用提示，不用演示分数填充。

体型图片识别、设备模拟仍属于实验功能，不列为已完成的真实识别或硬件接入。两位同学的详细边界继续以 [实习生分工](intern_tasks_and_mobile_plan.md) 为准。
