# 用户流程实测与下一步

日期：2026-11-24。本轮使用独立临时数据库和虚构账号，未修改现有用户库。

## 现在实际能做到什么

浏览器里走通了：注册 → 首次测评 → 生成训练计划 → 选计划中的深蹲 → 解析短视频 → 开始训练 → 刷新恢复 → 结束训练 → 查看报告 → 从历史记录找回报告。

视频解析使用推荐的 RepCount 深蹲片段 `repcount_stu4_66.mp4`，浏览器 MediaPipe 提取到 55 帧姿态。姿态提取是真实执行的；本轮没有启动真实评分、动作计数服务，报告正确显示“暂无有效评分”和“演示 / 备用结果”，不计成绩，也不自动调整处方。

这说明主流程已经能运行，尚不能据此认定算法有效或成品已经验收。

## 本轮发现并修复的问题

| 问题 | 修复后的表现 |
| --- | --- |
| 首次进入也提示“登录过期” | 只有曾登录的账号凭证失效时才提示过期；新访客正常进入登录页 |
| 打开报告后登录，原来的页面丢失 | 登录后回到原页面，保留训练编号等参数；拒绝外部返回地址 |
| 后端暂时不可用，被带回登录页 | 单独显示连接失败与重试入口，保留账号缓存；恢复后重试回原页面 |
| 错误网址显示空白 | 显示“没有找到这个页面”，提供首页和训练历史入口 |
| 负腰围、零臀围也能保存 | 页面和接口都拒绝无效数值，不写入记录；有效小数可保存 |
| 身高、体重等输入无效时显示原始错误对象 | 显示对应字段的中文提示，失败不修改已保存档案 |
| 体型页默认填写未经测量的围度，演示点击像真实识别 | 围度初始为空；主要功能改为实测记录，模拟部位解析单独折叠并说明 |
| 恢复视频训练后提示重新选文件，但文件输入不可用 | 明确说明已保存姿态可直接生成报告，视频预览不会恢复 |
| 视频训练也显示摄像头采集说明，未解析就称已解析 | 根据输入方式和实际数据状态显示说明 |

接口数值上限用于拦截明显输入错误，不是临床正常范围。BMI、腰臀比保留计算展示，不作新的健康风险分级。

## 接下来优先做什么

1. **A 同学：让普通用户一进来知道该点哪里。** 按现有分工完成个人首页、未完成训练入口、角色导航；移除“图14”“CoT”等开发文案。普通用户目前仍能看到审核和管理入口，虽然审核页有权限拦截，体验上仍容易误解。
2. **B 同学：把测评填写解释清楚。** 现在需要输入 0–100 的换算分，普通人不知道怎么得到；先标明填写来源、逐项提示、提交后的下一步。无测评分数时如何开始，由负责人确认，不补默认分或自行制定医学换算规则。
3. **主线：部署到 HTTPS 测试地址后做真机验收。** 先验收注册、视频训练和报告，再检查 Android / iPhone 摄像头授权、后台暂停、弱网、退出恢复。当前仍是本地验证，不是已上线。
4. **负责人：接通并验证算法服务。** 用固定视频记录真实计数、评分和失败表现。没有真实结果时继续保留明确的备用提示，不用演示分数填充。

体型图片识别、设备模拟仍属于实验功能，不列为已完成的真实识别或硬件接入。两位同学的详细边界继续以 [实习生分工](intern_tasks_and_mobile_plan.md) 为准。

## 后续补齐：开始响应丢失后刷新恢复

同一标签页现在只暂存开始请求编号、动作、计划编号和输入方式，并按用户隔离。刷新先向服务端查原请求：已建立则恢复原记录，已结束则打开原报告，已取消则返回历史；暂未查到仍保留原编号，重新准备输入后沿用编号重试。检查接口断网时暂停新建。关闭标签页或清除站点数据后，仍需从训练历史找回；未保存的姿态数据不会因此恢复。

同时修复了计划读取失败时静默进入自由训练的问题。当前计划接口只有明确返回“没有计划”才允许自由训练，服务异常时显示重新加载入口。通过训练编号恢复旧训练直接读取原记录，不依赖最新计划是否变化或能否读取。

本轮另用独立临时库 `ah-start-recovery-20261124.db`、虚构测试账号完成浏览器验收。测试服务器临时模拟一次“开始记录已经提交，但向浏览器返回 503”，该故障模拟没有加入产品代码：

| 操作 | 结果 |
| --- | --- |
| 加载推荐深蹲视频 | 浏览器 MediaPipe 实际解析得到 55 帧 |
| 点击开始，模拟响应丢失 | 显示检查原请求及重试入口，锁定原动作和输入方式 |
| 刷新同一标签页 | 自动找回训练 #1，原姿态数据保留 |
| 结束并生成报告 | 打开训练 #1 的报告，显示 55 帧；无真实评分和计数时明确提示暂无结果 |
| 核对临时数据库 | 总计 1 条训练，状态 finished，保留 55 帧，没有重复记录 |
| 390 像素宽度 | 恢复页无横向溢出；仍未验证手机真机或摄像头权限 |

最终回归：前端 41 项、后端 55 项通过，生产打包通过。新增自动检查覆盖同一请求刷新恢复、暂未查到后沿用编号、恢复接口断网、账号隔离、已结束记录跳转、计划服务异常、非法输入及不覆盖旧数据。验证后已关闭临时测试服务器。

## 后续补齐：部署前的数据备份与恢复

新增 `scripts/backup_data.py`，支持停站后备份 SQLite 数据库与上传文件、独立校验、恢复到新的空目录。使用 SQLite 快照保留已提交的 WAL 数据，逐文件检查大小和 SHA256，并检查数据库完整性及主要数据表记录数。非空目标直接拒绝；完整校验通过前不写入恢复目标；复制中断清理本次创建的文件。上传内容与数据库引用保持一致仍要求停站，不支持在线整体备份。

本轮新增 29 项检查，全部使用临时数据库、两个虚构账号和合成文件：

| 检查 | 结果 |
| --- | --- |
| 备份后恢复到新目录，使用恢复后的数据库提供 API | 原密码可登录，旧报告和历史可读，未完成训练可继续保存 |
| 上传文件 | 字节保持一致，训练中的相对文件引用仍指向恢复后的文件；未验证合成文件的实际视频播放 |
| 切换另一个账号 | 原用户训练、报告和文件仍不可访问 |
| WAL 中已提交的数据 | 快照包含最新修改，恢复值一致 |
| 归档内容或清单被改动、数据库损坏、归档截断 | 拒绝校验或恢复，目标目录保持不动 |
| 越界路径、Windows 特殊文件名、符号/硬链接、重复文件 | 拒绝恢复，不执行通用解压操作 |
| 目标目录已有数据 | 拒绝覆盖，保留原文件 |
| 复制中途模拟磁盘错误 | 清理本次创建文件，原空目录保持为空 |
| 备份中途文件变化或读取失败 | 不发布正式归档，不残留部分归档 |
| 从其他工作目录分别执行三个命令 | 备份、校验、恢复均成功，不依赖后端模块导入 |

Docker 镜像已配置包含工具，手机部署文档补齐更新前备份、空数据卷恢复、原卷保留和恢复后验收步骤。本机没有 Docker，因此容器启动、服务器恢复和手机真机验收仍未执行。两位实习生的页面和 `a`、`b` 分支未修改。

最终回归：后端 84 项通过（含新增 29 项备份/恢复检查），前端 41 项通过，生产打包和改动格式检查通过。后端依赖库仍有一条既有弃用提示。以上检查未使用或修改本机实际用户数据库。

## 后续补齐：手机摄像头训练的中断与亮屏处理

训练实际采集时尝试申请浏览器亮屏控制，暂停、结束、切后台或离开后释放。浏览器不支持、系统省电拒绝或中途回收时明确提醒；允许手动重试，不反复自动申请，也不阻断训练。不会修改手机系统设置。

相机轨道被系统终止时关闭旧预览、暂停计时及采集，并尝试将已有数据保存到原训练。保存失败仍沿用未保存提示和重试流程。未开始训练的预览和未完成的开启请求切后台也会关闭，迟到的权限或模型响应不能重新启动旧采集。

摄像头权限拒绝、无设备、设备占用分别给出中文恢复方法；不安全 HTTP 和不支持相机的浏览器在开启前提示。恢复到没有姿态帧的训练时，说明还需继续采集，不再宣称可以直接生成报告。

新增 12 项自动检查：亮屏请求去重、暂停后迟到的响应释放、暂停后立即继续的竞争、离开释放、浏览器拒绝或回收及显式重试、不支持与后台页面降级、实际 Vue 响应式状态联动、相机中断及监听清理、模型加载期间中断、中断后原训练保存、后台关闭预览和摄像头错误分类。相机和亮屏的系统边界使用替代实现。

另使用独立临时数据库 `ah-mobile-camera-20261124.db` 和虚构账号，在浏览器请求 390×844 的视口检查恢复训练：内容宽度与可见宽度均为 375 像素（滚动条占宽），无横向溢出；原训练 #1、预设的 00:03 采集时长保持，手动保存成功，刷新仍恢复同一记录，空姿态点击结束会提示继续采集。本轮没有申请真实相机权限，没有拍摄视频，未验证手机系统的实际锁屏、摄像头或 HTTPS 部署行为。

最终回归：前端 53 项、后端 84 项通过，生产打包和改动格式检查通过。后端仍有一条既有依赖弃用提示；未使用本机实际用户数据库。
